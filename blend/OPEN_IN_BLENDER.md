# Opening "BEHIND TWO WINDOWS" in Blender

There are two ways in. Pick based on which Blender you have.

---

## Route A — just open a .blend  (needs Blender 5.3 or newer)

Double-click any file in this folder, or **File → Open**:

| File | What's in it |
|---|---|
| `S01.blend` … `S10.blend` | One sequence each: the full set, both characters animated, the camera keyframed |
| `characters.blend` | Aarav and Maya on their own — walk cycle, idle breathing, blinks |

Each file opens ready to play:

* The frame range is already set (e.g. S06 is frames 1–456 at 24 fps) — press **Spacebar** to play.
* The viewport is already in the exact shading the film was rendered with
  (Solid / Studio / `rim.sl` / Object colour / shadows + cavity).
* The camera is active — press **Numpad 0** to look through it.
* Renders are pointed at `//renders/`, so **Render → Render Animation** writes PNGs next to the file.

**Check your version first:** Blender → top-right of the splash, or **Help → About**.
If it says 4.x, these files will refuse to open (Blender reads older files, never newer ones).
Use Route B instead.

---

## Route B — build the scene from the scripts  (works in Blender 4.x and 5.x)

This is how the film was actually made, and it is version-proof.

1. Put the `source/` folder somewhere you can find it, e.g. `D:\behind_two_windows\source`.
2. Open Blender → **Scripting** workspace → **New** text block.
3. Paste this, change the one path, and press **Run Script** (▶):

```python
import sys, importlib

PROJECT = r"D:\behind_two_windows\source"   # <-- the folder holding rig.py, sets.py, shots.py
SHOT    = "S06"                             # S01 … S10

if PROJECT not in sys.path:
    sys.path.insert(0, PROJECT)

import render3d
for m in ("rig", "sets", "look", "shots", "render3d"):
    importlib.reload(sys.modules[m])

n, mood = render3d.build(SHOT)
print(f"built {SHOT}: {n} frames, mood '{mood}'")
```

The scene appears in the viewport. Change `SHOT` and run it again to build a different
sequence — the script clears the scene each time.

### Seeing it the way the film looks

Route B leaves the viewport on Blender's defaults. To match the film:

* Viewport shading → **Solid**, then open the dropdown beside it and set
  Lighting **Studio** → `rim.sl`, Color **Object**, tick **Shadow** and **Cavity**.
* Or just set the render engine to **Workbench** and press **F12**.

The sky, colour grade, bloom and grain are *not* in Blender — they are composited
afterwards by FFmpeg (`look.py` paints the sky, `render3d.py` applies the grade). So a raw
Blender render will show the geometry over a plain background. That is expected.

## Editing things

Everything is generated by code, so the useful edits are in the scripts, not the .blend:

| What you want to change | Where |
|---|---|
| A character's clothing, skin, hair, proportions | `rig.py` — the colour constants at the top, and `Character.__init__` |
| How a character walks, sits, points, waves | `rig.py` — `walk()`, `sit()`, `point_at()`, `raise_arm()` |
| Furniture, buildings, props, the city | `sets.py` |
| Staging, performance, camera moves, shot lengths | `shots.py` — one function per sequence, plus the `SHOTS` table at the bottom |
| Sky colours, grade, bloom, vignette per sequence | `look.py` — the `MOODS` dictionary |
| Narration text, music, sound effects | `audio10.py` |

To rebuild the whole film after an edit:

```bash
python3 audio10.py all                  # narration, score, effects
python3 render3d.py shots S01 S02 ...   # re-renders only the shots you name
python3 assemble10.py                   # edit, titles, mix, final MP4
```

`render3d.py` needs the `bpy` module (`pip install bpy`) and FFmpeg on the PATH. If you'd
rather render from the Blender you already have, run it as:

```bash
blender --background --python render3d.py -- shot S06
```
